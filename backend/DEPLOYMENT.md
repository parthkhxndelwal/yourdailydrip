# Daily Drip Medusa backend - production deployment

Deploys the Medusa v2 backend (`apps/backend`, `@dtc/backend`) to a VPS with
Docker Compose and a Caddy reverse proxy that terminates TLS for
`api.yourdailydrip.com`. Companion to todo 16 of
`.omo/plans/medusa-storefront-integration.md`.

## Architecture

```
                         Cloudflare DNS
                              |
                    A record api.yourdailydrip.com -> VPS IP
                              |
                         [ Caddy :80/:443 ]   (TLS, ACME, email from CADDY_EMAIL)
                              |   reverse_proxy medusa:9000
                         [ medusa :9000 ]     (internal only - never published)
                              |   DATABASE_URL=postgres://...@postgres:5432/medusa
                         [ postgres :5432 ]   (named volume postgres-data)
```

- Only Caddy publishes host ports (80/443). Medusa's `:9000` is reachable only
  inside the compose network.
- Data survives `docker compose restart` via the `postgres-data` named volume.
- Single replica assumption: the iThink tracking job (`*/30 * * * *`) is
  designed for one backend replica (no distributed lock). Do not scale the
  medusa service without revisiting that job.

## Prerequisites

- Ubuntu 22.04 or 24.04 VPS (2 GB RAM is comfortable; Medusa builds in ~5 min).
- Domain `yourdailydrip.com` with DNS control (your registrar or Cloudflare).
- A mailbox to receive Let's Encrypt expiry notices (`CADDY_EMAIL`).
- Real test credentials, generated by a human before going live:
  - Razorpay test keys + webhook secret + account number (dashboard).
  - iThink staging credentials + warehouse approval (~24h).
  - Publishable API key (created from the admin UI, step 7 below).

## 1. DNS

Point an A record at the VPS IPv4 address:

```
api.yourdailydrip.com.  3600  IN  A  <VPS_IP>
```

Wait for propagation (`dig +short api.yourdailydrip.com` from your machine
should print the VPS IP) before starting Caddy - ACME issuance needs the name
to resolve publicly.

## 2. Install Docker on Ubuntu

```bash
# Convenience script (pinned by checksum on the install page) or:
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker compose version   # needs the compose plugin, present with get.docker.com
```

Add your user to the docker group to run compose without sudo:

```bash
sudo usermod -aG docker "$USER"
# log out and back in
```

## 3. Firewall

Only SSH, HTTP, HTTPS:

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

Do not open 9000 - Medusa must stay internal.

## 4. Clone and set secrets

```bash
sudo mkdir -p /opt/yourdailydrip
sudo chown "$USER" /opt/yourdailydrip
git clone <repo-url> /opt/yourdailydrip
cd /opt/yourdailydrip/backend

cp .env.example .env
chmod 600 .env
```

Fill `backend/.env` with real values:

| Variable | How to get it |
| --- | --- |
| `JWT_SECRET`, `COOKIE_SECRET` | `openssl rand -base64 32` (one each, different values) |
| `POSTGRES_PASSWORD` | `openssl rand -base64 24` |
| `CADDY_EMAIL` | your mailbox (Let's Encrypt account) |
| `RAZORPAY_ID`, `RAZORPAY_SECRET` | Razorpay dashboard > Settings > API Keys (test mode) |
| `RAZORPAY_ACCOUNT` | Razorpay dashboard > Settings > Account Details |
| `RAZORPAY_WEBHOOK_SECRET` | Razorpay dashboard > Settings > Webhooks (create one for the URL in step 7) |
| `ITHINK_*` | iThink team (staging); `ITHINK_BASE_URL=https://pre-alpha.ithinklogistics.com/api_v3` |
| `STORE_CORS` / `AUTH_CORS` | `https://yourdailydrip.com,https://<preview-subdomain>.workers.dev,http://localhost:5173` (see CORS section) |
| `ADMIN_CORS` | `https://api.yourdailydrip.com,http://localhost:9000` |

Required variables are enforced by compose (`${VAR:?}`): `docker compose up`
refuses to start with a clear message if `POSTGRES_PASSWORD`, `JWT_SECRET`,
`COOKIE_SECRET`, `CADDY_EMAIL`, or any `RAZORPAY_*` is missing.

> **Razorpay is required to boot.** The razorpay provider's `validateOptions`
> throws at startup without real `RAZORPAY_*` credentials, so the medusa
> container will crash-loop until they are set. `ITHINK_*` are optional: the
> provider boots without them and checkout surfaces readable errors.

## 5. Build and start

```bash
cd /opt/yourdailydrip/backend
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml logs -f medusa
```

Wait for the medusa healthcheck to turn green (`docker compose ps` shows
`healthy`). Then verify:

```bash
curl -s https://api.yourdailydrip.com/health        # 200 "OK" (liveness)
curl -s https://api.yourdailydrip.com/admin/ready   # 200 {"status":"ok"} (DB readiness)
```

- `/health` is liveness only - it stays 200 even when Postgres is down.
- `/admin/ready` is the DB-readiness probe: it races a `SELECT 1` against a 3s
  timeout and returns `503 {"status":"error"}` when Postgres is unreachable.
  Use it in uptime monitors instead of `/health`.
- When the medusa container is stopped, Caddy returns `502` immediately (fast
  fail, no hang). `docker compose restart` recovers the stack; data survives
  because Postgres and its volume are separate.

## 6. First-run setup (inside the container)

All commands target the running `medusa` service (WORKDIR is
`/app/apps/backend`):

```bash
cd /opt/yourdailydrip/backend
P="docker compose -f docker-compose.prod.yml exec -T medusa"

# 1. Migrations + storefront bootstrap (required before anything else).
#    storefront-bootstrap.ts seeds the sales channel, publishable keys, store,
#    India region, India Warehouse (full address incl. postal code), calculated
#    iThink shipping options (Standard=Delhivery, Express=Blue Dart) and the
#    Rooted Hair Growth Oil product. Runs exactly once (script_migrations).
$P npx medusa db:migrate

# 2. Admin user
$P npx medusa user -e admin@yourdailydrip.com -p '<strong-password>'

# 3. Publishable API key token (the key itself is seeded by db:migrate; its
#    freshly generated token must be read from the admin UI)
#    https://api.yourdailydrip.com/app > Settings > Publishable API keys >
#    "Storefront Publishable Key". Give the value to the storefront as
#    MEDUSA_PUBLISHABLE_KEY (todo 17).

# 4. iThink env (backend/.env): ITHINK_BASE_URL/ACCESS_TOKEN/SECRET_KEY/
#    PICKUP_ADDRESS_ID/GST_NUMBER — without them calculated rates error at
#    checkout. The India Warehouse postal code (from_pincode) is seeded as
#    110006; update it if the pickup address changes.

# 5. Razorpay webhook (Razorpay dashboard)
#    URL: https://api.yourdailydrip.com/hooks/payment/razorpay_razorpay
#    Events: payment.captured / payment.failed (the plugin's webhook handler
#    maps events to payment sessions via the notes patch, see
#    apps/backend/patches/razorpay-webhook-notes.md). Webhook secret must
#    match RAZORPAY_WEBHOOK_SECRET.
```

## 7. CORS

Medusa enforces CORS at the HTTP layer. Allowed origins must be listed in
`backend/.env` (no wildcard with credentials - browser cookies are used for
customer auth):

| Origin | Purpose | Env |
| --- | --- | --- |
| `https://yourdailydrip.com` | production storefront | STORE_CORS, AUTH_CORS |
| `https://<preview-subdomain>.workers.dev` | Cloudflare preview deploys (update per deploy) | STORE_CORS, AUTH_CORS |
| `http://localhost:5173` | local dev storefront | STORE_CORS, AUTH_CORS |
| `https://api.yourdailydrip.com` | admin dashboard (same-origin, listed for completeness) | ADMIN_CORS |
| `http://localhost:9000` | local dev admin | ADMIN_CORS |

Compose defaults cover production + localhost; the preview origin must be
added to `backend/.env`.

## 8. Product images (v1 caveat - important)

Seeded product images are deterministic static references to the local dev
asset server (`http://localhost:5173/src/assets/<file>`) - they will NOT load
from the VPS. The storefront bundles the same images locally
(`storefront/src/assets/p-*.jpg`), so the catalog renders fine from the
storefront; Medusa-side URLs only matter for admin surfaces.

- v1 (accepted): keep static URLs; if admin-facing images matter, re-point the
  product image URLs to a public static host (e.g. a Cloudflare R2 public
  bucket) via the admin UI. No code change needed - image URLs are plain data.
- Admin uploads (future): configure the Medusa file module with an
  S3-compatible provider (`@medusajs/file-s3`, R2 endpoint + access keys) and
  add the env vars to `backend/.env`. Out of scope for v1 - recorded as a
  deferred decision.

## 9. Postgres backups

`pg_dump` cron on the VPS host (dumps from inside the container, no network
exposure). Install as `/etc/cron.d/medusa-backup`:

```
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
0 3 * * * root mkdir -p /var/backups/yourdailydrip && docker compose -f /opt/yourdailydrip/backend/docker-compose.prod.yml exec -T postgres pg_dump -U medusa medusa | gzip > /var/backups/yourdailydrip/medusa-$(date +\%F).sql.gz && find /var/backups/yourdailydrip -name "medusa-*.sql.gz" -mtime +30 -delete
```

(Adjust `-U`/db name if `POSTGRES_USER`/`POSTGRES_DB` differ. Cron needs the
`%` escaped.) Every night at 03:00 it writes a compressed dump and keeps 30.

Restore (drops and recreates the target database contents):

```bash
cd /opt/yourdailydrip/backend
gunzip -c /var/backups/yourdailydrip/medusa-YYYY-MM-DD.sql.gz | \
  docker compose -f docker-compose.prod.yml exec -T postgres psql -U medusa medusa
```

Recommended hardening (explicitly deferred): copy dumps off the VPS
(restic/rclone to S3) and verify restores quarterly. Recorded as a deferred
decision in `.omo/notepads/medusa-storefront-integration/decisions.md`.

## 10. Upgrades

```bash
cd /opt/yourdailydrip/backend
git pull
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml exec -T medusa npx medusa db:migrate
```

> If `npm install` changed the lockfile upstream, remember the razorpay
> webhook-notes patch must be re-applied to `node_modules` (see
> `apps/backend/patches/razorpay-webhook-notes.md`).

## 11. Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| medusa container restarting | Empty `RAZORPAY_*` - provider `validateOptions` throws at boot. Set real test creds in `backend/.env` and `docker compose up -d`. |
| `502` from Caddy | medusa container down (intentional fast-fail). Check `docker compose logs medusa`; `docker compose restart`. |
| `503` from `/admin/ready` | Postgres unreachable - readiness probe answers in ~3s by design. Check the postgres container + volume. |
| ACME/TLS not issued | DNS not propagated, or port 443 blocked by UFW. `docker compose logs caddy`. |
| Storefront CORS errors | Origin missing from `STORE_CORS`/`AUTH_CORS` in `backend/.env` (check the Cloudflare preview origin). |
| Generic endpoints hang ~60s on PG loss | Known framework behavior (knex acquire timeout); `/admin/ready` is the sanctioned fast probe. |
